# Task routing

Use the start hook's effective policy. Preserve the parent model, effort and overrides; honor higher-priority instructions, host capabilities and authorization. Hooks do not dispatch work.

Before substantial work, select an owner and call a suitable allowed delegation tool; a plan is not delegation. Parent familiarity is not a reason to retain transferable work: hand over scope, materials, decisions, constraints, acceptance and authority; assess separation of edits, trials and tests. Return ordinary work after Pro advice or parent-only intervention to the suitable owner; see effective.md. Respect host limits and parent-only work; explain only retained substantial transferable work once. Parallel work requires independent parent work; serial delegation requires permission and concrete benefit. Do not bypass role limits.

For investigation use Luna; for ordinary implementation and fixes use Terra; for difficult execution use Sol. Prefer enabled Pro for consultation when permissions, materials and access suffice; use Astra only when needed. Separate evidence collection from difficult judgment and return the latter to root for reassessment. A root Sol may delegate a concrete difficult unit to Sol only for a specific separation benefit; do not transfer needlessly to the same model. Use the effective default efforts and permitted hierarchy from the hook; do not infer role or depth from the model. New independent repository units are candidates for Cloud first; suitable consultation may use user-enabled Chat Pro only under the actual host, authorization and actor constraints. Use the [bundled Pro runner](references/chat-transfer.md#one-browser-call) for dispatch and recovery; never resend. A plan is not permission.

Local resources do not rule out a child with access. Bundle related creative work and checks; coupling alone does not require parent ownership. Keep a suitable owner, do not force parallelism, and honor higher-priority constraints.

Before cloud model selection involving credentials, follow [local authentication](references/local-auth.md); children return authentication needs to their parent. Never move secrets or assume a queued handoff is authenticated. Read relevant references: [delegation](references/operating-guide.md#standard-delegation) and [handoff](references/operating-guide.md#handoff), [Cloud and session choice](references/session-routing.md), [Chat routing](references/chatgpt.md) and [authorization](references/chat-authorization.md), [observation](references/observation.md), or [configuration](references/configuration.md). Preserve custom principles, return contradictions to root, and never rewrite user configuration or trust settings.

The opt-in [Haiku API route](references/haiku-api.md) is a root-owned candidate for ordinary or substantial work, subject to host and target permission. Use local-auth for approved, tool-free text proposals; the parent applies edits and tests. It is separate from Chat and native child models; hooks never start it.

The opt-in [Muse Ember pilot](references/muse-pilot.md) is root-owned, single-use and text-only. Its planner never calls MCP; root verifies permission, status and results. No default routing change or uncertain retry.
