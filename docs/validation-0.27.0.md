# 0.27.0 の検証記録

## 動機と変更

限定された制作タスクの一例では、素材・スクリプト・表示調整を親が同じ工程として続け、内部の結合を理由に挙げていました。該当ターンの補助フック状態には作業系呼出しが4件記録され、既存の8件の閾値に達していませんでした。フックが観測する呼出しと表示上の操作は同じ単位ではなく、イベント配送の網羅性や実際の担当の素材・ツール利用可否も確認できていません。この一例は全タスクの原因やモデルの性能を示すものではありません。

方針の意味変更として、制作工程の編集・素材・表示確認を一つの完了単位として引き継げるか検討し、単位内部の密結合と親子間の密結合を区別します。短い仕事、適任の既存担当、実際のアクセス、引継ぎ負担、上位制約と並列・直列の条件を維持します。

配布変更として、識別子のあるrootの `UserPromptSubmit` で、そのターンの初回記録時に短い条件付き案内を返します。子や重複には返さず、prompt本文の内容や作業の大小を検査せず、処理の拒否やモデル起動を行いません。既存のSQLite schemaと8件の作業後の助言は維持します。入力ごとの追加コンテキスト量は増えます。`parent_guard.py status` の `reminders` は8件後の助言数であり、入力時の案内数や実配送数ではありません。

現行の[公式 UserPromptSubmit 実装](https://github.com/openai/codex/blob/main/codex-rs/hooks/src/events/user_prompt_submit.rs)は `additionalContext` を受け付けます。このソース確認とローカルの合成イベント検査は、利用中のホストがイベントを配送しモデルへ注入する証明ではありません。

## 検証と限界

Windows / Python 3.13の権限付きテストプロセスで `python -m unittest discover -s tests -v` は414件成功し、`python scripts/check_package.py` も成功しました。新規テストは初回と重複、子と識別子欠落、本文が状態に保存されないこと、配布コマンドの応答形式、描画した方針の条件を検査します。これは実際のホストで案内が届くことや委譲が実行されることを保証しません。

カスタムsummaryの変更は自動適用しません。新しい既定summaryを既存カスタムsummaryへ勝手に移さず、適用後も個別の詳細overrideを確認します。0.27.0の実ホスト配送・新たな実委譲、他OS、Cloud・通常Chat・Haikuでの影響は未検証です。稼働中の旧版が参照されている間のライブupgradeは旧版ファイルを削除し得るため避け、利用環境への導入は別途確認します。
