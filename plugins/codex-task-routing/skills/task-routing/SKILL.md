# Task routing

Use the start hook's effective policy. Preserve the parent model, effort and overrides; honor higher-priority instructions, host capabilities and authorization. Hooks do not dispatch work.

Before substantial investigation or implementation, select an owner and call an allowed, suitable delegation tool; a plan alone is not delegation. Parent familiarity or prior work is not a reason to retain a transferable unit: briefly hand over scope, materials, decisions, constraints, acceptance and authority, and include separation of future edits, trials and tests in the benefit assessment. Continue a suitable delegated owner. Short work, genuine parent-only operations, acceptance, prohibitions and host restrictions can remain with the parent; state a concrete reason. Parallel work requires useful independent parent work; serial specialist delegation requires host permission and concrete added value. Do not transfer solely for the same model or bypass role limits.

For local Codex work use Terra as the default for ordinary implementation and investigation; use Sol for agreed-design elaboration or a documented Terra capability gap. Use the effective default efforts and permitted hierarchy from the hook; do not infer role or depth from the model. New independent repository units are candidates for Cloud first; other suitable substantial work may use user-enabled Chat Pro only under the actual host, authorization and actor constraints. Consult the relevant detailed route before acting, and do not treat a plan as execution or permission.

Local-resource needs do not rule out a child with access. Bundle related creative edits, materials and checks as one completion unit: internal coupling does not itself require parent ownership. Keep a suitable delegated owner, do not manufacture independent parent work or force parallelism, and apply custom principles and higher-priority constraints.

Before cloud model selection involving credentials, follow [local authentication](references/local-auth.md); children return authentication needs to their parent. Never move secrets or assume a queued handoff is authenticated. Read relevant references: [delegation](references/operating-guide.md#standard-delegation) and [handoff](references/operating-guide.md#handoff), [Cloud and session choice](references/session-routing.md), [Chat routing](references/chatgpt.md) and [authorization](references/chat-authorization.md), [observation](references/observation.md), or [configuration](references/configuration.md). Preserve custom principles, return contradictions to root, and never rewrite user configuration or trust settings.

The opt-in [Haiku API route](references/haiku-api.md) is a root-owned candidate for ordinary or substantial work, subject to host and target permission. It is separate from Chat and native child models; hooks never start it.
