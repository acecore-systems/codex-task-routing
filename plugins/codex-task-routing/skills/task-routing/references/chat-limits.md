# 通常Chat 6 Proの利用枠と許可確認

分類は「適任の主担当候補を選ぶ」処理で、送信や外部書込みの許可ではありません。契約価格だけでChat経路を有効化せず、他の利用者の契約・親設定・overrideを保持します。

## 上限の確認（2026-09-15）

[OpenAI公式ヘルプのGPT-6 Pro / Sol Pro limits](https://help.openai.com/en/articles/20001354-gpt-5-6)では、Pro $200の6 Proは週200メッセージ、Sol Proは別に日170メッセージ、両モデル合計では日200メッセージです。6 Pro週次上限後はThinkingのMediumへ自動切替されます。通常Chatの枠はWork/Codexとは別です。これは確認日時点の公開仕様で、将来の保証や固定した実装定数にしません。Sol Proを追加ルートにする設定でもありません。

最新の公式情報と実アカウント表示を確認します。修正・追加確認も予算に含め、ルーターから送った件数だけで他のChat利用を含む実残量を断定しません。固定の日次配分や月曜リセットを作りません。別モデルへの変更を6 Proの成果と扱わず、待機または既存承認内のCodex担当へ戻します。Work・モデルAPI・追加購入へ暗黙に切り替えません。

## 利用方法の許可は別に確認する

[個人向け利用規約](https://openai.com/policies/row-terms-of-use/)には自動・プログラム的なデータやOutputの抽出と制限迂回についての禁止が記載されています。Browser機能、Pro契約、週次上限の範囲内という事実だけで、具体的な自動送信・回収が許可済みとは判断しません。自動回収を含む積極運用の拡大前に、公式に認められる経路・条件を確認し、根拠を利用者側で保持してください。この版は例外適用を確認していません。

分類方針と経路の有効化・拡大は分離します。転送方法の許可が不明なら、liveのtransport_authorizedをfalseとし送信を止めます。設定を有効にするだけで承認されたことにしません。秘密・認証・会話履歴を取得せず、データ共有、接続先の操作、PR、マージ、配備の承認をそれぞれ守ります。

## 観測・受入・比較

送信直前にroot、opt-in、許可済み転送、surface、6 Pro、制限通知、今回の操作の承認を確認し、chat_plan.pyの--liveへ新しい観測だけを渡します。これは入力された主張の照合であり、アカウント状態の自動取得や残量の証明ではありません。モデル表示は送信前後で確認し、実行backend IDは取得不能なら不明です。

同程度の仕事・同じ合格条件で、Astra親の従来構成、Sol親でChatなし、Sol親で6 Proを優先する構成を比較します。通常作業と難しい判断は分け、対象版と検証環境をそろえます。まず子のeffortとChat適合条件をそろえ、親変更の差を分けます。既存の通常作業3件の観測枠を使い、親子合計のCodex使用量、Chatメッセージ、初回受入、手戻り、人の修正、重大な見落としを区別します。追加の比較情報は短い検証記録として残し、未対応の台帳キーを捏造しません。欠測理由を保持し、サンプル完了と比較データの充足を混同せず、モデル別割合だけで節約率を主張しません。
