# ルーティングの実行確認（2026-11-03）

## 今回確認できたこと

稼働版0.24.0の開始フックは有効方針への参照と方針hashを今回のコンテキストに注入しました。カスタム原則があるため、有効方針を読んで担当を判断しました。配布コードのSessionStartには、まとまった調査・実装の前に担当を選び、適合し許可される場合は実際の委譲ツールを呼ぶ指示があります。フック自身は仕事を起動しません。

親は、ローカルな稼働状態との繰り返し照合が必要な今回の工程にCloudや通常Chatを選ばず、標準子に `gpt-6.1-terra` / `xhigh` を要求して起動しました。親は一覧で担当の実行中状態を確認し、担当はこの記録の調査を実施しました。これは今回の要求・起動・作業の証拠であり、バックエンドの実model・effortの独立検証ではありません。利用可能な機能と上位指示が優先され、短い仕事、既存の適任担当、委譲禁止やホスト制限などでは親が継続できます。

## 原因と限界

方針が届くこと、担当を選ぶこと、実ツールで起動することは別の段階です。依頼に基づき、別の6セッションについてそれぞれ直近2ターンを確認しました。子への実装委譲や既存担当への継続依頼がある一方、子と並行して親も通常実装を進めた例と、ローカル現物の確認を理由に親が作業を継続した例がありました。これは全面的な未委譲ではなく、親が通常工程を保持する場合があることを示します。ツールイベントの件数は工数やトークン量ではありません。対象は限定的で、全期間・全セッションや全作業の実態、親の実modelやbackend、個々の判断の妥当性までは確定できません。

0.25.0では、ローカル現物が必要なことと標準子によるアクセス可否を分け、親の並行作業を作るためだけに独立した通常実装を親へ残さないことを既定方針に明記しました。実際に並行できる重要判断等を親が持つ場合に限定し、有用な独立作業がなければ並列を強制せず、直列委譲のホスト許可と追加価値を要します。短い仕事、密結合、適任の継続担当、親が実装する正当な場合と上位制約は尊重します。方針の意味変更であり、自動実行や委譲の保証ではありません。

継続作業への補助的な注意喚起は、一定数の対象ツール呼出しを観測した場合に限る非強制の仕組みです。子の起動や担当への連絡を観測したターンでは助言が抑制されるため、親と子が共に実装する場合の検出には使えません。`functions.exec` が対象名として届けば外側の呼出しは数えられますが、wrapper内部の個々の操作は観測しません。今回の各イベントの名前・相関・注意喚起の配送は未検証です。ローカルの集計状態が存在することだけでは、実配送の網羅性や委譲成功を示せません。Cloud、通常Chat、他のホストでの実動作も今回検証していません。

## 検証

0.24.0では `python scripts/check_package.py` が成功し、全件テストはサンドボックス内で一時ディレクトリやハードリンクに対する権限制約で失敗したため、権限付きのテストプロセスで再実行し392件成功しました。0.25.0の結果は[検証記録](validation-0.25.0.md)に分けます。テストは合成入力での動作確認であり、実ホストでの今後の委譲を保証しません。

0.25.0は稼働環境へ導入していません。カスタム `principles.summary` は既定summaryを置換するため、新しい既定summaryは自動では反映されません。カスタム原則や利用者の設定を自動編集せず、衝突はrootが判断します。稼働中のプラグイン、認証情報、会話履歴は変更していません。
