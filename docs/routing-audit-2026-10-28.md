# Routing 利用状況の確認（2026-10-28）

## 稼働版の確認

開始フックは0.19.0の有効方針を注入していました。配布済みの`routing.py status --json`は`ok: true`、cacheは`valid`、競合診断は空でした。これは方針の解決と今回の注入の証拠であり、あらゆる仕事で適切な委譲が行われたことの証明ではありません。

稼働設定で選定対象になっていたのはLuna/max、Sol/xhigh、Astra/mediumです。旧`models.terra`は互換専用で、GPT-6.1 Terraの選定には使われていませんでした。ホストの利用可能モデル一覧には`gpt-6.1-terra`があり、設定への追加と実際の利用可否は分けて確認します。

個別設定にはSolのeffort・上限、summary、local-auth原則の上書きがあります。summaryは既定文の更新後も保持されるため、新モデルの導入時にはモデル表だけでなく文章の整合も確認する必要があります。今回、稼働設定や親のmodel/effortを変更していません。

## 利用の証拠と限界

- [0.19.0検証記録](validation-0.19.0.md)には、2026-10-27の実Cloudでのテスト、新規UIセッション作成、同一タスクのnative継続・回収、独立した2文書の並列作業と統合が記録されています。今回その実操作を再実行したわけではありません。
- `observation status --json`は3件完了、進行中0件、残枠0件、使用量欠測3件でした。親子合計の使用量や節約率は算出できません。監査のためだけに観測枠を増やしたり会話履歴を走査したりしていません。
- ホストの実行model/effortとhook trustはstatus上では`unknown`です。今回の開始フック出力は確認できましたが、要求設定だけからバックエンドの実行設定を断定しません。

したがって「方針は有効で、委譲経路の実証もある」が確認結果です。「常に最適に振り分けられている」「利用量が削減できた」とまでは判断できません。

## 今回の変更と導入境界

GPT-6.1 Terraを実装・修正・テストの正式な候補へ追加する0.20.0を、専用ブランチで実装しました。旧Terra overrideの意味を黙って変えず、Solとの性能序列を創作せず、通常Chatの権限も自動拡張していません。

リポジトリの変更・テスト・PRと、利用環境への導入・次回開始フックへの反映は別の段階です。稼働中のプラグインへの自動インストールは行わず、変更版の検証結果と未検証範囲は同版の検証記録に残します。

## 今回の標準子への委譲

実装・通常修正・検証はSol子へまとめ、親は並行して稼働設定の診断と利用実績の証拠整理を担当しました。実装完了後、利用者のTerra活用の依頼に基づき、標準子を`gpt-6.1-terra/xhigh`指定で起動し、旧override互換・summaryの保持・通常Chat権限境界に限定した読み取り専用レビューを依頼しました。その間、親は公開物・検証記録の確認とPR準備を担当しました。

Terra指定の子の起動は受け付けられ、同じ担当からレビュー完了結果を回収しました。修正を要する具体的な指摘はありませんでした。全件テストの重複実行はしていません。これは今回の指定・起動・作業回収の証拠であり、内部バックエンドの識別、性能・使用量の比較、0.20.0の利用環境への導入成功を示すものではありません。
