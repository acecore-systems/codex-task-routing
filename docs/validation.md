## 0.3.1: 通常作業の観測記録

Windows / Python 3.13で全60テストと配布パッケージ・manifest・skill検証を通過しました。観測は一時Codexホームで確認しています。

- 通常作業3件の予約、同taskの再送、設定確認の除外、方針内容ごとの保存先分離。版だけが変わった場合は同じ観測群を継続します。
- 記録完了・欠測・部分的な使用量の区別。未完了run、途中turn、未知カウンターを実測充足として扱わず、キャッシュと推論の内数関係を検証します。
- 再開時の既存run・取得済み値・検証参照の保持。不正入力・破損・書込競合で既存記録を上書きせず、方針フックの配信は続けます。
- プロセスを一時ホーム内で異常終了させても、OSロックが解放され後続の記録を続けられること。
- 保存済みのキーで旧観測群を更新でき、別の群が破損・満杯でも走査・変更しないこと。
- 公開用の親/子入力例を実際のCLIプロセスから受理し、3枠使用後はフックが新規開始コマンドを追加しないこと。

実際のCodex CLI `0.154.0-alpha.6.2`を使った一時ホームへの導入・再導入・解除も成功し、導入コピーの両フックが所定の形式を返すことを確認しました。利用中の設定・フック信頼・プラグインは変更していません。以前の自動更新・Windowsタスク登録機能に変更はありません。

通常会話でAIが記録を最後まで更新する実績と、品質や契約使用量の削減は未確認です。台帳は渡された構造化データの整合を検証するもので、実行モデル・使用量の自動取得や、提出された根拠自体の真偽の検証は行いません。親の最終turnが未完了なら欠測を残し、全体の節約率を確定しません。

## 再実行

Python 3.11以上で、リポジトリ直下から実行します。

```text
python -m unittest discover -s tests -v
python scripts/check_package.py
python scripts/smoke_native.py --output-dir outputs/native-check
```

最後のコマンドにはCodex CLIが必要です。PATH外の実行ファイルは `--codex` で指定できます。出力先は未作成のディレクトリを指定してください。検証用ホームと `result.json` を残し、ユーザーのCodexホームへ書き込みません。初版から次版へのローカル更新を模擬します。

GitHub ActionsではWindows・Linux・macOSのPython 3.11で単体テストとパッケージ検査を実行します。対象commitの実際の結果はPRのChecksを参照してください。Codexホストの動作まで3 OSで検証するものではありません。

## 未検証・制約

- ユーザーがフックを信頼した後の、実際の通常タスクへのイベント配信。
- 日常の仕事におけるmodel/effort選定と、下位モデルからの適切な返却。合格した単体テストだけでは品質や節約を証明できません。

競合検出は既知の分担見出し・正本名を探す限定的な診断です。各ディレクトリでは非空の `AGENTS.override.md` を優先します。独自のfallbackファイル名・プロジェクトルート設定・表現の異なる同種の指示を網羅するものではありません。symlink・Windowsのreparse pointを含む入出力パスは保護のため拒否します。
