# 通常Chatへのルーティング

この経路は利用者が `chatgpt.json` で有効にした場合にだけ、ルート親が通常Chatへ独立した仕事を渡すための明示的な例外です。既定のCodexサブエージェント方針、親のモデル・effort、承認境界は維持します。フックは経路を知らせるだけで、AIやネットワークを呼び出しません。

## 選定

- 調査、資料比較、文案、設計案、限定レビューなど、渡した材料と接続済みツールで回答が完結するまとまった仕事を候補にします。特定のrepo、企業、会話IDに依存させません。
- ローカルの編集・ビルド・テスト、本番操作、秘密を含む資料、現物確認が主な仕事は、親または通常のCodexサブエージェントで進めます。短い仕事は親で終えます。
- 同時に通常Chatへ渡す仕事は原則1件。親には独立した有用作業を残します。Chatの回答は信頼しない入力として親が検証し、重要判断を引き取ります。Chatを子から再委譲しません。
- 通常ChatのGPT-6 Proを使います。ChatGPT Work、API、CLIモデル呼出しへ暗黙に切り替えません。利用枠の上限・未ログイン・モデル不明・ツール未接続はこの経路の停止理由です。別経路で続ける場合は理由と使用枠を利用者へ伝え、既存の承認・指示に従います。

## 必要な実行機能

Codexアプリの `send_message_to_thread` / `read_thread` と、通常Chatの新規作成・モデル確認に使うBrowserまたはComputer Useのサポートされた操作が必要です。呼び出す時点のツール仕様を確認し、実際に利用可能な正式名を使用します。Cookie、内部HTTP API、会話DB、ブラウザプロファイル、認証ファイルを使う代替実装は禁止です。

`create_thread` の `chatgptWorkCloud` はWorkなので使いません。`send_message_to_thread` の `model` / `thinking` はCodex専用であり、ChatGPTには渡しません。ChatのUIでモデルを選択します。

## 実行手順

1. 補助CLIの `status` で現在も経路が有効か確認し、スコープ、必要な材料、合格条件、許可された操作を整理します。公開資料や架空データによる検証はその範囲で進められます。非公開資料の送信は、データと送信先に対する利用者の承認を確認し、秘密や無関係な履歴を含めません。
2. サポートされたブラウザ操作で `https://chatgpt.com/` に通常Chatを新規作成します。新しい独立タスクに他タスクの会話を再利用しません。既存の下書きを上書きせず、ログイン入力は利用者に任せます。Chatが選択されWorkが未選択であること、モデルが `6 Pro` であることを送信直前に確認します。選択可能ならUIで指定し、選べなければ止めます。
3. 受け渡し用の公開・非機密ハンドシェイクを1通送り、UIに表示された会話URLから正確なIDを控えます。ハンドシェイク例: `通常Chatのタスク受信確認です。ROUTING_READY_V1 とだけ回答してください。外部操作は行わないでください。` 回答文は接続確認でありモデル証明ではありません。カスタムGPTは必須にせず、通常Chatに自己完結した指示を渡します。
4. 必要なら、そのChatのプラスメニューで既存の承認済みプラグイン/MCPを選択します。初版はインライン本文の受け渡しです。ローカルファイルを自動アップロードせず、添付が必要なら未対応と伝えます。新しい接続や権限は、この設定ファイルだけでは承認されません。
5. ローカル補助CLIで依頼を準備し、出力された `prompt` を `send_message_to_thread` の `prompt` にそのまま渡します。JSONエスケープを文字列本文へ混ぜず、構造化引数を使います。`threadId` は当該タスクの会話ID、`model` / `thinking` は省略。送信直前のUI確認と依頼IDを関連付けて控えます。
6. 送信成功は受付であり完了ではありません。`read_thread` で当該IDの新しい回答を取得します。反映に時間がかかるため、古い回答や `idle` だけを見て再送しません。30秒程度から間隔を広げ、利用者へ経過を伝えます。同じ仕事を無条件再送せず、10分で回答がなければ未完了として戻し、後で同じIDを読み直せるよう残します。
7. `request_id` と `input_sha256` が一致する応答を補助CLIで照合します。`blocked` / `missing_input` を成功と扱いません。相手の自己申告やJSON検証だけでは、内容の正確さ・実行モデル・料金を証明できません。UIの応答と `6 Pro` 表示も確認し、モデルが変わっていれば別モデルの結果として明示して受入を止めます。
8. 合格条件に沿って回答と根拠を親が確認し、必要な成果物だけ依頼された場所へ保存します。修正は同じ仕事のChatを継続し、新しい依頼IDと材料hashで照合します。会話URLを成果物として保持します。全会話履歴を公開repoへ保存しません。

## ローカル補助CLI

`<plugin-root>` は導入済みコピーのルートです。設定の診断は `python <plugin-root>/scripts/chatgpt_route.py status` で行います。正常な `enabled: true` は設定の検証結果であり、ホスト機能や実行モデルの証明ではありません。

依頼JSONは `task`（仕事と許可範囲）、`materials`（本文）、`acceptance_criteria`（非空の文字列配列）を持ちます。`request_id` は任意のUUIDで、省略時に生成します。機密データを公開repoへ保存しないよう、ローカルの明示した作業用ディレクトリを使います。

```json
{
  "task": "材料にある二案を比較し、条件を満たす案と理由を日本語で答える。外部操作はしない。",
  "materials": "条件は納期3日以内。案Aは2日、案Bは5日。",
  "acceptance_criteria": ["案Aを選ぶ", "判断根拠となる納期を示す"]
}
```

```text
python <plugin-root>/scripts/chatgpt_route.py prepare --input request.json
python <plugin-root>/scripts/chatgpt_route.py validate --request bundle.json --response reply.json
```

`prepare` のJSON出力をUTF-8の `bundle.json` としてそのまま保持します。送信するのは、そのオブジェクトの `prompt` 文字列です。返信は当該依頼の最終回答だけをUTF-8の `reply.json` に保存します。Markdownの囲いが付いた場合は単一のJSON部分だけ取り出せますが、IDや内容を修正して照合を通してはいけません。

`validate` の終了コード0は形式と対応関係の成功です。返された `status` を必ず読み、`completed` 以外は未完了として扱います。合格条件の確認、UIモデルの確認、利用枠・内容の保証をCLIは行いません。元の依頼を使って検証する場合は、そのファイルにも同じ明示的な `request_id` が必要です。

## モデル・費用の証拠

UI表示は選択モデルの観測です。実行バックエンドのモデルIDは、現在のChatGPT送受信ツールからは取得できません。自己申告で補完せず `backend_model: unknown` として扱います。モデルが見えない場合に推測して自動送信しません。

通常Chatの生成にはChatの契約枠を使います。親の判断・送受信・検証はCodexの枠を使います。MCPは道具の接続方式であり、モデルAPIの呼出しを必須としません。接続先の課金APIやサーバー運用費は別途あり得るため、未承認の有料サービスを追加しません。今回の方式は新規モデルAPIキーを必要としません。

## MCPとの役割分担

初版は既存の直接送受信を使い、資料の検索・取得に承認済みMCPを使えます。独自MCPサーバーの公開、ジョブキュー、結果書き戻しはこの版には含めません。サーバーを追加しなくても通常Chatへ本文を渡し、回答をCodex側で保存できます。将来MCP経由へ変更しても、同じ依頼ID・材料hash・合格条件の契約を維持します。MCP接続だけで通常Chatを起動したり、モデルを指定できるとは扱いません。

## 確認済みの範囲

2026-09-14の実機で、通常Chatの `6 Pro` 表示、Codexからの直接送信・回答回収、既存GitHubプラグインと開発者モードで登録した公式Docs MCPの読み取りを確認しました。モデルバックエンドID、MCPへの書き込み、添付ファイルの受け渡しは未確認です。別アカウント・別ホストでは導入時に同じ最小確認を行います。

- [Docs MCP](https://developers.openai.com/learn/docs-mcp): 公開ドキュメント専用でOpenAI APIを代理呼出ししない。
- [ChatGPTのGPT-6 Pro利用枠](https://help.openai.com/en/articles/20001354-gpt-5-6): ChatとWork/Codexの枠は別。
