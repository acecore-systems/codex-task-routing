# 0.24.0 の検証記録

## 変更と測定範囲

既定方針には、まとまった調査・実装の前に担当を決め、適合し許可された委譲は実ツールを呼び、親継続時は理由を一度示す規則を追加しました。これは方針の意味変更です。短縮と詳細の参照化は配布変更です。ユーザーのoverrideを変更せず、カスタム原則を持つ場合はモデル・役割の判断前に有効方針を読む必要があります。方針hashとrevisionは変わり、既存観測のsampling keyとは区別されます。

Windows・Python 3.13で同一の一時Codexホーム、同一のインストールパスを使い、0.23.2（HEAD d081a06）と今回のhookの生成文字数／UTF-8バイト数を比較しました。通常Chatは有効／無効の両方、カスタムは短いsummaryとChat有効の合成設定です。パス長と状態で数値は変わります。

| 生成物 | 0.23.2 文字 / バイト | 0.24.0 文字 / バイト |
| --- | ---: | ---: |
| SessionStart、既定 | 4,660 / 9,198 | 2,140 / 2,140 |
| SubagentStart、既定 | 2,912 / 2,912 | 1,779 / 1,779 |
| SessionStart、Chat有効 | 6,635 / 11,173 | 2,925 / 2,925 |
| SessionStart、カスタムsummary＋Chat | 4,554 / 5,044 | 2,728 / 2,728 |
| SKILL.md | 19,054 / 19,068 | 2,792 / 2,792 |

これは静的な生成文の長さであり、詳細参照、子の起動、引継ぎ、再作業を含む総トークンや契約利用量の節約を示しません。実使用量の比較は未実施です。

## 自動検証と限界

Windows / Python 3.13 で `python -m unittest discover -s tests -v` は391件成功し、子の再委譲禁止の文言を明確化した後に関連する23件も再実行して成功しました。`python scripts/check_package.py` も成功しました。sandbox内では一部の既存テストの外部一時領域とハードリンクが拒否されたため、承認された権限付きのテストプロセスで全体を再実行しました。合成イベントは短い仕事、閾値、重複、欠けたID、子の呼出し、spawn失敗、既存担当への連絡、子が稼働中、壊れた状態、未観測と助言0件の区別を検査します。助言文は親の受入、本人の禁止やホスト制限を例外として明示しますが、フック自身は依頼内容・実際の既存担当・委譲の適否を判定しません。

公式の現行[PreToolUse実装](https://github.com/openai/codex/blob/main/codex-rs/hooks/src/events/pre_tool_use.rs)では`session_id`、`turn_id`、`tool_use_id`を入力に含め、`additionalContext`を受け付けます。[UserPromptSubmit実装](https://github.com/openai/codex/blob/main/codex-rs/hooks/src/events/user_prompt_submit.rs)もセッションとターン識別子を渡します。これは確認時のソース仕様であり、利用先ホストや版でイベントが届くこと、識別子が期待どおり相関すること、助言がモデルに反映されることの証明ではありません。フック再信頼、新版の実ホスト配送、実際の標準子起動・担当継続、他OS、Cloud/Chat、本番導入は未検証です。フックが存在しないホスト、対応外ツールやwrapper内部は観測できません。`status`はローカル状態の存在と破損だけを示し、検知の網羅性や委譲成功を保証しません。

専用の一時ホーム以外のCodex設定、ユーザーのAGENTS、親モデル・effort、稼働中プラグイン、認証情報や会話履歴は変更・取得していません。
