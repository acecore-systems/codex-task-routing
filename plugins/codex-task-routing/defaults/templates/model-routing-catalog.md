# 作業分類表 — 固定effortと通常Chat優先

この表は担当候補であり、親の設定変更・送信・外部書込みの許可ではない。短い通常作業は親で終える。基準運用は親Terra/{{models.terra.default_effort}}、子はLuna/{{models.luna.default_effort}}・Sol/{{models.sol.default_effort}}・Astra/{{models.astra.default_effort}}。Terra子は標準ルート外。既存overrideの有効な固定値を使う。

## 選定の順序

まとまった工程では、Chat経路が有効であれば6 Proを最初の主担当候補にする。難問だけに限定せず、必要情報・実ツール・対象権限・検証環境でその工程を完結できるかを見る。短い残作業、Codex側の現物への頻繁な照会、機密を渡せない場合、準備・検収が過大な場合はCodexに残し、理由を一言残す。上位モデルから下位へ、または下位から上位へ順番に試す必要はない。

並列分担は親にも有用な独立作業が必要。直列の専門委譲は具体的な追加価値とホストの許可を確認する。許可不明・禁止なら起動せず、不要な親の仕事や別CLIで条件を迂回しない。

## 調査・文書・事務

| 作業条件 | 候補と合格条件 |
| --- | --- |
| 指定原文の項目取得、抽出、固定列の照合 | 親、またはまとまった工程はLuna。対象・必要項目・ページング・0件と未取得の区別を固定 |
| 公開情報・承認済み接続先の調査・比較 | 実取得ツールが使える6 Proを優先。出典・対象版・日付・確認範囲・未取得を返す |
| 要件整理、分析、設計、矛盾・反例の検討 | 6 Proを主担当候補。利用不能なら通常は親、複雑な整合はSol、難しい前提はAstra |
| 文案・翻訳・報告書・資料レビュー | まとまった工程は6 Pro。短い整形は親。高影響の表現は根拠と承認を確認 |
| 帳票の網羅確認、日付や欠測の解釈 | 原本を実見できる親Terraまたは6 Pro。OCR空欄だけで記載なしとしない |
| 認証・課金・税務・個人情報に関する判断 | 事実取得と重要判断を分離。適任の専門判断・最新の公式根拠・必要な人の承認を省略しない |

## 実装・運用・PR

| 作業条件 | 候補と合格条件 |
| --- | --- |
| 一意の局所修正、通常の実装・検証 | 親Terraで完結。少量の仕事を別のTerraへ渡さない |
| 既知手順のまとまった取得・処理・テスト実行 | Luna。異常原因の推定・未知の環境構築は親へ返す |
| Chat側にrepoの取得・編集・テスト・PR作成の実機能がある | 明示承認された工程を6 Proの候補にする。Chatだから実装不可と決めない |
| 分析とローカル実行が分離できる | Codexで証拠取得→6 Proで判断→親または専門子で実装・検証。細かい往復を増やさない |
| Codex側の編集・テスト・新規ログ確認が密に反復する | 複雑な工程はSol。難しい設計前提・重大な不確実性はAstra |
| DB移行、本番変更、セキュリティ境界、不可逆な操作 | 専門判断・復旧条件・受入証拠・明示承認を確認。PR作成はマージや配備の許可ではない |
| 必要な実機・接続・権限がない | 未検証範囲を明示して返す。別環境のテストを実機検証と扱わない |

Chatへ実装を任せる時は、repo・base/head・対象範囲、許可するcreate/update/commit/PR等の操作、テスト環境・合格条件をtaskとhandoffへ明示する。機能の提供、対象権限、今回の承認は別々に確認する。承認されない試験書込みで権限確認しない。マージは明示許可とCI・レビュー・対象SHA確認がある場合だけ。現物アクセス不足を別の仕事の成果で埋めない。

## 画像・成果物・データ

画像は実際に閲覧できる担当と専用ツールを使う。固定項目の照合と意味・原因判断を分け、正確な寸法・色値・画素差は測定する。資料・表計算の成果物は内容だけでなく表示・式・対象範囲も必要に応じて検証する。全件確認が必要な項目を代表確認で代替しない。数値の合計だけで取得網羅性や親子の使用量範囲を証明しない。

## 受入と再配分

子の結論・重要差分・証拠・前提・反例・未解決点を受け取る。親の取りまとめと専門判断を分け、同じ分析やテストを理由なく全面再実行しない。設計変更・範囲拡大・矛盾・検証不能・同じ失敗は親へ返す。effortは固定しても担当や合格条件を固定しない。接続・権限・材料不足をモデル変更で解決したと扱わない。
