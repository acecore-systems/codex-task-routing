# 0.23.2 検証記録

2026-10-29、Windows・Python 3.13.15の専用worktree（branch `codex/shorten-session-injection`、origin/main 6aec757から作成）で確認しました。

## 上限の由来と単位

- 字数上限 `MAX_ADDITIONAL_CONTEXT_CHARS = 8000` は初版（fa786a1）から、「hooks.jsonはトークン基準の上限を持つ。実行時がホストに方針を途中で切り詰めさせないよう、独立した保守的な字数上限を置く」という意図で入っていました。Chatや他ホストの字数制限を根拠にしたものではなく、保守的な目安です。
- Codexの一次情報（openai/codex、タグ `rust-v0.165.0-alpha.1.2`）:
  - `codex-rs/hooks/src/engine/discovery.rs`: `additionalContextLimit`は SessionStart と SubagentStart などで有効です（他のイベントでは無視して警告します）。
  - `codex-rs/hooks/src/output_spill.rs`: `approx_token_count(text) <= token_limit` なら素通しします。超えると全文を一時ファイルへ退避し、head/tailのプレビューとパスに置き換えます（エラーにはなりません）。未指定時の既定は `DEFAULT_HOOK_OUTPUT_TOKEN_LIMIT = 2,500` です。
  - `codex-rs/utils/string/src/truncate.rs`: `approx_token_count = ceil(UTF-8バイト数 / 4)` です。
- リポジトリの `hooks/hooks.json` は、SessionStartとSubagentStartの routing 行に `additionalContextLimit: 8000` を持ちます（この版では変更していません）。
- 新しい上限は、8000トークン × 4バイト = 32,000バイトから、4,000バイト（12.5%）の余裕を引いた 28,000バイトです。余裕は、ホストの推定式が版ごとに変わる場合や、additionalContextの外側に表示文が付く場合を見込んだ値です。
- 字数とバイト・トークンの比は一定ではありません。日本語は1字3バイト、英数字は1字1バイトです。現行の注入（Chat有効、導入先271字、観測campaign有効）は7,170字・11,708バイト（概算2,927トークン）で、ホストの上限8,000トークンの約37%です。字数上限は、この比を考えずに日本語の多い注入を実際の上限より厳しく制限していました。単位を揃えたことで、この過剰な制限を外しました。

## 規則の扱い

- 変更したのは `scripts/routing.py` のコード内文言だけです。`defaults/`、`effective.md`、`principles.summary`、`model-routing-*.md` は変えていません。`policy_revision` と provenance も変わりません。
- 削った一文は「Keep authentication local.」です。同じ規則（認証情報・OAuth JSON・Cookie・認証画面を手元に残す）は、ローカル認証の文に残っています。
- 言い換えは、ローカル認証の導入文、Chat転送経路の注記（一時Chatとレガシー転送）、ホームの注記（「detailed policy files」→「detailed files」）です。規則・禁止事項・数値・ツール名・条件は変えていません。
