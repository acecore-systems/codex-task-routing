# Task routing

Avoid a classifier-only model call or repeated full tool inventories. For a substantial Chat candidate, reuse the scoped, expiring capability inventory and deterministic `chat_plan.py` checks in [capability reuse](references/chat-capabilities.md); short work needs no extra planning files. Use [local transfer](references/chat-transfer.md) when supported Browser DOM operations can move the prepared prompt and final response without echoing their full text into the parent's context. These helpers do not authorize dispatch, attest a model, or replace semantic acceptance.

For an enabled normal Chat route, evaluate Chat suitability before choosing a native child for each substantial independent work unit; users need not mention this plugin again. Prefer 6 Pro for work that can finish with approved materials and verified tools when preparation, waiting, acceptance and rework are proportionate. Use 6 Pro as the initial main specialist, including implementation, testing and PR creation when the actual tools, scoped write approvals and verification environment suffice. Split analysis from Codex-only execution when useful. Small work or repeated inspection of Codex-only resources stays in Codex. Use the route reference's selection and handoff checks; enabling Chat does not grant data sharing or tool permissions.

Use the effective policy already supplied by this plugin's start hook. Keep the user's chosen parent model and effort. It authorizes choosing suitable standard subagents only within the user's task, available tools, and higher-priority instructions. The reference parent is Sol/xhigh and does normal work itself. Do not create a child solely to hand off ordinary parent work. Automatic child effort uses the effective default_effort: GPT-6 Luna/max, GPT-6 Sol/high, GPT-6 Astra/high in bundled defaults; preserve explicit overrides. Parallel delegation needs useful independent parent work. Serial specialist delegation requires concrete added value and explicit host permission; do not invent parent work or bypass higher-priority restrictions. Short work stays with the current capable agent.

When the hook explicitly reports the opt-in ChatGPT Chat route enabled, the root parent may use [normal Chat routing](references/chatgpt.md) as the user-enabled exception for substantial work supported by the actual Chat capabilities and approvals, including research, design, review, implementation and PR creation. Read that reference and [usage/authorization gates](references/chat-limits.md) before dispatch. Run chat_plan.py with fresh --live observations; candidate classification never authorizes a dispatch. Contract price, enabled settings or installed tools do not establish permission for automatic extraction. Missing transport authorization blocks dispatch. Use normal Chat with the required UI model `6 Pro`, never Work or a model API, and match request IDs and input hashes. The default `browser-temporary` transport uses supported Browser operations to create one Temporary Chat, send the real request once, and read the final answer; never call `send_message_to_thread` for that Temporary Chat. `codex-app-tools` remains a legacy transport only when an existing setting explicitly selects it. The helper prepares and validates local data only. Missing capability or unknown model blocks this route. Do not route from subagents. If the opt-in is absent or invalid, retain the standard Codex child policy.

If no effective policy was supplied, run `python <plugin-root>/scripts/routing.py status --json`, where plugin-root is two directories above this skill folder. Inspect conflicts and errors before calling the policy active. Do not silently replace existing global or project instructions. Read only the relevant section of the resolved policy and catalog; use the handoff reference when needed. Loading this skill alone does not install or trust its hooks.

For a handoff, specify the model and effort explicitly, purpose, scope, approved actions, completion criteria, evidence, return conditions, and either the independent parent work for parallel delegation or the added value and host permission for serial specialist delegation. Reuse a suitable existing child for follow-up, with only the change and new evidence. Recheck model and effort availability from the current host; config values are requests, not proof of execution. Return important evidence, assumptions, counterexamples and unresolved judgments to the parent. Reuse valid specialist work rather than redo it; parent coordination does not replace required specialist or human approval. PR creation permission is not merge/deployment permission. Do not recommend a model for the user's next message.

For substantial normal work, use the observation allowance supplied by the start hook. While a slot remains, record the start with a stable root-task/work-unit ID and follow [observation](references/observation.md) to close that same record before the final answer. Keep the returned sampling_key with the ID across resumptions and child results; close the original sample even if policy changes. Three work units per effective policy content are enough; audits, setup, and short questions do not consume slots. Record unavailable usage with a reason rather than leaving the work unrecorded. A closed record does not imply complete usage coverage. The recorder accepts supplied metadata; it does not collect conversation logs or prove model execution. Do not launch agents, repeat checks, or scan history just to fill fields.

For configuration requests, consult [configuration](references/configuration.md). Preserve unrelated settings and keep overrides outside the plugin cache. Show the requested differences and validate them. Natural-language principle changes require reviewing related summary and detailed sections; schema validation does not prove semantic consistency. Never edit credentials, user memories, parent model settings, or hook trust records.

For an explicit request to enable automatic updates on Windows, run `python <plugin-root>/scripts/install_updater.py install`. Use `status` to inspect or `uninstall` to stop it, and `install --dry-run` to preview without registration. This registers a per-user background task, without changing how the user opens Codex or sending model requests. Every 15 minutes while the user is logged in, it checks whether Codex and ChatGPT are closed; running or unknown state skips the update. The updater preserves the registered Git ref and user overrides. Never run a marketplace upgrade from a live session hook: native upgrades can remove the old plugin files used by active tasks. Automatic checks do not guarantee an update during prolonged app use or immediately before a normal launch. Diagnostics are in `<CODEX_HOME>/codex-task-routing/updater/state/last-sync.json`; no raw CLI logs are retained. Registration is currently Windows-only; other systems can use the one-shot `scripts/updater.py` command. Do not silently install a scheduler from a routing hook.
