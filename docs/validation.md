## 再実行

Python 3.11以上で、リポジトリ直下から実行します。

```text
python -m unittest discover -s tests -v
python scripts/check_package.py
python scripts/smoke_native.py --output-dir outputs/native-check
```

最後のコマンドにはCodex CLIが必要です。PATH外の実行ファイルは `--codex` で指定できます。出力先は未作成のディレクトリを指定してください。検証用ホームと `result.json` を残し、ユーザーのCodexホームへ書き込みません。初版から次版へのローカル更新を模擬します。

GitHub ActionsではWindows・Linux・macOSのPython 3.11で単体テストとパッケージ検査を実行します。対象commitの実際の結果はPRのChecksを参照してください。Codexホストの動作まで3 OSで検証するものではありません。

## 未検証・制約

- ユーザーがフックを信頼した後の、実際の通常タスクへのイベント配信。
- 日常の仕事におけるmodel/effort選定と、下位モデルからの適切な返却。合格した単体テストだけでは品質や節約を証明できません。
- 別PC・他OSのCodexホスト。モデルとeffortの利用可否はホストごとに確認が必要です。
- 自然言語の上書きによる意味の矛盾。要約と関連する詳細節を合わせてレビューしてください。

競合検出は既知の分担見出し・正本名を探す限定的な診断です。各ディレクトリでは非空の `AGENTS.override.md` を優先します。独自のfallbackファイル名・プロジェクトルート設定・表現の異なる同種の指示を網羅するものではありません。symlink・Windowsのreparse pointを含む入出力パスは保護のため拒否します。
