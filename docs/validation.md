# 初版の検証

検証日: 2026-09-14。対象: `codex/initial-plugin` の0.1.0実装。

## 確認した範囲

- 既定の詳細方針・分類表・引継ぎ例が、配布向けに調整した正本スナップショットと一致すること。
- モデル・effort・分担原則の部分上書き、未知キー・型違い・範囲外・重複キー・未解決参照の拒否。
- 生成物のhash、出力先の保護、開始・再開・子の開始イベント用のコンテキスト、旧指示との競合検出。
- 公式plugin-creatorのmanifest検証、skill-creatorのスキル検証、同梱ファイルの構成と公開前検査。
- Windows上のCodex CLI `0.154.0-alpha.6.2` で、一時的なCodexホームへの登録・導入・版更新・解除。既存設定・指示・上書きファイルを保持し、導入されたコピーから診断と両イベントのフック出力を確認。

通常の利用環境の設定・指示は変更していません。CLI検証はモデルへのリクエストを送らず、フックの信頼設定も変更しません。

## 再実行

Python 3.11以上で、リポジトリ直下から実行します。

```text
python -m unittest discover -s tests -v
python scripts/check_package.py
python scripts/smoke_native.py --output-dir outputs/native-check
```

最後のコマンドにはCodex CLIが必要です。PATH外の実行ファイルは `--codex` で指定できます。出力先は未作成のディレクトリを指定してください。検証用ホームと `result.json` を残し、ユーザーのCodexホームへ書き込みません。初版から次版へのローカル更新を模擬します。

GitHub ActionsではWindows・Linux・macOSのPython 3.11で単体テストとパッケージ検査を実行します。対象commitの実際の結果はPRのChecksを参照してください。Codexホストの動作まで3 OSで検証するものではありません。

## 未検証・制約

- ユーザーがフックを信頼した後の、実際の通常タスクへのイベント配信。
- 日常の仕事におけるmodel/effort選定と、下位モデルからの適切な返却。合格した単体テストだけでは品質や節約を証明できません。
- 別PC・他OSのCodexホスト。モデルとeffortの利用可否はホストごとに確認が必要です。
- 自然言語の上書きによる意味の矛盾。要約と関連する詳細節を合わせてレビューしてください。

競合検出は既知の分担見出し・正本名を探す限定的な診断です。表現の異なる同種の指示を網羅するものではありません。symlink・Windowsのreparse pointを含む入出力パスは保護のため拒否します。

## 正本からの調整

元のモデル、effortの既定値、分担条件は保持しています。個人パス、導入日の履歴、従来の共通指示からの参照経路を配布形式へ変更しました。個人用の内部ログ解析スクリプトは同梱せず、実行情報を取得できない場合は欠測として扱います。effortコードと重複する日本語表示名は、上書き後に古い表示が残らないよう整理しました。元ファイルのhashと調整内容は `defaults/provenance.json` にあります。
